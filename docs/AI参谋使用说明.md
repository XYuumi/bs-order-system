# AI 参谋使用说明（v1.19）

AI 参谋把 AI 从“写一段摘要”推进到接单交付流程：风险雷达先给出可复现的事实与分数，模型只解释和排序；体检、回访、验收清单都可以直接回到订单业务流。

## 一、入口与权限

| 能力 | 入口 | 接口 | 权限 |
| --- | --- | --- | --- |
| 风险总览 | 侧栏「AI 参谋」`/ai` | `GET /api/ai-ops/overview` | 管理员 / 写手 |
| 今日作战简报 | AI 页 Hero / 工具台 | `POST /api/ai-ops/risk-brief` | 管理员 / 写手 |
| 需求书体检 | AI 页工具台、风险行、订单详情 | `POST /api/ai-ops/requirement-review` | 管理员 / 写手，且可见该订单 |
| 客户回访 | AI 页工具台、风险行 | `POST /api/ai-ops/reply` | 管理员 / 写手，且可见该订单 |
| 验收清单 | AI 页工具台、风险行 | `POST /api/ai-ops/acceptance` | 管理员 / 写手，且可见该订单 |
| 订单上下文联动 | 订单详情「AI 参谋」 | 跳转 `/ai?order=订单号` | 同上 |

代理（agent）不能进入 AI 参谋接口，返回 403；写手与管理员复用订单访问权限。

## 二、风险雷达

### 评分规则

分数由 `server/app/routers/ai_ops.py` 的 `_risk_of` 计算，只使用数据库事实：

| 信号 | 分值 |
| --- | --- |
| 未设置交付期限 | +14 |
| 已逾期 | +42，且每逾期 1 天 +3（上限 +18） |
| ≤2 天到期 | +34 |
| ≤7 天到期 | +20 |
| 待开始 | +12；下单超过 3 天仍未开工再 +8 |
| 制作中但未指定负责人 | +16 |
| 已完成待结单 | +8 |
| 售后中 | +20 |
| 没有程序包或演示视频 | +10（已完成单 +18） |
| 已完成但缺程序包 | +10 |
| 需求书为空 | +8 |
| 没有任何客户跟进 | +4 |
| 制作 ≥10 天且 ≤7 天到期 | +6 |
| 已完成/结单但客户未验收 | +5 |

分数封顶 100；`≥60` 高风险，`30–59` 关注，`<30` 安全。按分数降序、期限升序排列，最多返回 40 条；KPI 统计在制/售后订单、高风险、7 天内到期、需求书缺失与平均分。

### 今日作战简报

只把风险前 10 单交给模型，模型必须回 JSON，并只保留来自真实清单的单号；最多 5 条优先级。没有在制订单时直接返回空状态，**不调用模型、不消耗 AI 配额**。

## 三、需求书体检

输入订单号，读取该订单当前需求书，最多取前 7000 字。返回：

- `score`：综合分 0–100；
- `dimensions`：6 维评分（目标清晰度、需求完整度、技术可落地、验收可测试、前后一致性、交付明确度）；
- `issues`：最多 6 条，按 high/medium/low 排序，含问题、原文依据与可直接采用的建议；
- `highlights`：最多 3 条做得好的地方；
- `metrics`：字数、章节数、量化描述数、是否含验收/技术栈。

没有需求书返回 400，不调用模型；模型返回结构异常返回 503，不把原始 JSON 暴露给页面。

## 四、客户回访

请求：

```json
{ "order_id": "260101-001", "scene": "progress", "tone": "warm" }
```

- 场景：`kickoff` 开工问候、`progress` 进度同步、`risk` 风险沟通、`acceptance` 验收提醒、`aftersale` 售后关怀；
- 语气：`warm` 亲切、`professional` 专业、`concise` 简洁。

返回 `message`、`tips`、`suggested_time`。消息要求 160 字内、包含明确下一步或时间点、不泄露成本/真实价/毛利。页面提供「复制话术」与「记录到跟进」；后者写入 `POST /api/orders/{id}/notes`，内容前缀为 `【AI 回访话术】`。

若模型 JSON 解析失败，后端会尝试字段二次解析与正则提取；仍失败则返回 503，**不会把整段原始 JSON 当作消息显示**（v1.19 修复）。

## 五、验收清单

输入订单号，读取需求书（前 6500 字）和已上传文件，生成中文 Markdown，固定五章：

1. 交付物核对
2. 核心功能验收
3. 数据与权限
4. 兼容性与演示
5. 风险项与答辩备忘

每条使用 `- [ ]` 复选框，可在页面复制 Markdown 后贴到文档或逐项发客户确认。

## 六、配置、配额与安全

- 模型配置在「系统设置 → AI 中心」保存到数据库 settings：`deepseek_api_key/base_url/model/timeout`；`GET /api/settings` 只返回掩码。
- 默认模型 `deepseek-flash`；Key 不写入前端代码，不在接口响应中回显。
- 每个动作独立限流：同一用户/IP 每分钟最多 6 次（`rate_limit("ai_ops_<动作>")`）。
- 每日配额由 `AI_DAILY_QUOTA` 控制，`0` 表示不限制；每次调用写 `ai_usage`（scene、tokens、耗时、订单号、用户）。
- 所有动作写操作日志（`ai_risk_brief` / `ai_requirement_review` / `ai_reply` / `ai_acceptance`）。
- AI 超时由设置项控制（5–600 秒），前端请求超时为 120–180 秒。
- 空风险简报、无需求书、非法场景/语气等校验在调用模型前完成。

## 七、测试与故障排查

- 后端单测：`server/tests/test_ai_ops.py`（权限、风险规则、校验不调模型、空简报不耗配额、JSON 解析）。
- 浏览器专项：交付前以 Playwright 跑 19 项 AI 场景（27 路由、1920/390、风险雷达、简报、体检、回访写入跟进、验收清单、详情联动），结果见 `docs/全站E2E测试报告.md` 第十节。
- 常见问题：
  - 页面提示「未配置模型」：到 AI 中心确认 Key 与模型已保存，`GET /api/ai-ops/overview` 的 `ai_ready` 应为 true；
  - 体检/回访 503：模型返回空内容或结构异常，可重试；连续失败检查 Key 余额与网络；
  - 429：触发分钟限流，等待 1 分钟或检查是否有循环调用；
  - 代理账号 403：AI 参谋只对管理员/写手开放。
